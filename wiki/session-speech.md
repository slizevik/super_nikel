# Текст выступления по итогам сессии

В начале сессии SuperNikel умел сканировать локальную папку с PDF и сохранять извлечённый текст, но поиск выполнялся по целому документу. В базе была подготовлена модель chunks, однако она не участвовала в полном рабочем цикле.

За сессию мы построили последовательный pipeline индексации. PDF теперь разбирается на структурированные блоки с номерами страниц, координатами и заголовками секций. Детерминированный chunker собирает из этих блоков стабильные фрагменты с ограничением размера, overlap и metadata. Для каждого фрагмента предусмотрена embedding abstraction, проверка размерности и fake provider для локальной проверки. Chunks сохраняются в PostgreSQL вместе с embedding, страницей, heading и координатами текста.

Поиск разделён на два слоя. Full-text search находит точные термины через PostgreSQL. Vector search использует pgvector и cosine distance. Hybrid retrieval объединяет результаты обоих методов, нормализует оценки и выбирает лучшие фрагменты. Answers API передаёт модели только найденные chunks, а backend проверяет допустимость citations. В интерфейсе показываются документ, фрагмент, страница и секция.

Пользователь добавляет PDF в папку и нажимает «Сканировать папку». Backend сравнивает SHA-256 и ставит новые, изменённые или ещё не имеющие chunks документы в очередь. Worker извлекает текст, создаёт chunks и embeddings. Затем пользователь задаёт вопрос в чате, получает ответ по найденным фрагментам и может проверить исходную статью. История чатов сохраняется, новые сообщения отображаются сверху, отдельные чаты можно удалить.
