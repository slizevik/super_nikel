# AGENTS.md

## Правила работы агента

Этот файл описывает обязательный рабочий процесс агента в репозитории `super_nikel`.
Скрипты, на которые ссылаются правила, находятся в каталоге `hooks`.

## Перед началом работы

Перед началом новой задачи необходимо просмотреть последние записи агентских логов:

```powershell
powershell -File .\hooks\read-agent-logs-before-work.ps1
```

Назначение проверки:

- увидеть последние решения и ограничения;
- проверить состояние предыдущей работы;
- избежать повторения уже выполненных действий;
- учитывать незавершённые проблемы.

Если каталога `.agent-logs` нет, скрипт сообщает об этом и не блокирует работу. Если каталог пуст, работу можно начинать с чистого состояния.

## Безопасность критических операций

Перед опасными, потенциально разрушительными или критическими действиями необходимо запускать security guard:

```powershell
powershell -File .\hooks\security-guard.ps1 -Targets @('C:\develop\super_nikel\backend\app')
```

Проверка должна выполняться до операций, которые:

- удаляют файлы или каталоги;
- изменяют историю Git;
- выполняют reset или clean;
- пишут за пределами репозитория;
- работают с путями, которые могут находиться вне workspace;
- затрагивают базы данных или другие внешние ресурсы.

Security guard должен блокировать опасные шаблоны, включая:

- `rm -rf`;
- `Remove-Item -Recurse -Force`;
- `Delete-Item -Recurse -Force`;
- `git reset --hard`;
- `git clean -fd`;
- `DROP DATABASE`;
- `del /s /q`;
- `rmdir /s /q`;
- `git checkout -- .`.

Все целевые пути должны находиться внутри корня репозитория. Если guard завершается ошибкой, операцию нельзя продолжать без пересмотра команды и области действия.

Команда по умолчанию:

```powershell
powershell -File .\hooks\security-guard.ps1
```

## Работа с длинным выводом

Если команда возвращает большой лог или файл, вывод необходимо сокращать перед дальнейшим анализом:

```powershell
powershell -File .\hooks\tool-output-compress.ps1 `
  -InputPath .\logs\api\api.jsonl `
  -MaxChars 8000 `
  -MaxLines 200
```

Для обработки вывода через stdin:

```powershell
some-command | powershell -File .\hooks\tool-output-compress.ps1 -MaxChars 8000 -MaxLines 200
```

Правила компрессии:

- если вывод помещается в заданные лимиты, возвращать его полностью;
- если вывод превышает лимиты, сохранять начало и конец;
- явно сообщать размер исходного вывода и пропущенную середину;
- не пытаться анализировать усечённый вывод как полный лог.

## После изменения кода

После изменений Python, TypeScript или JavaScript необходимо запустить post-execution lint:

```powershell
powershell -File .\hooks\post-execution-lint.ps1 -ChangedFiles @(
  'C:\develop\super_nikel\backend\app\api\routes\documents.py',
  'C:\develop\super_nikel\frontend\src\App.tsx'
)
```

Если список изменённых файлов неизвестен, скрипт проверяет все файлы соответствующих типов в репозитории:

```powershell
powershell -File .\hooks\post-execution-lint.ps1
```

Проверки:

- Python: `ruff`, если установлен;
- Python: `mypy`, если установлен;
- TypeScript: `npx tsc --noEmit`, если найден frontend;
- JavaScript/TypeScript: ESLint, если он установлен.

Если Python-инструменты отсутствуют, Python lint может быть пропущен с явным сообщением. Ошибка TypeScript или ESLint должна считаться ошибкой проверки. Нельзя объявлять работу завершённой, если обязательная проверка завершилась с ошибкой.

## Общий порядок работы

Для каждой задачи соблюдать порядок:

1. Прочитать `.agent-logs` через `read-agent-logs-before-work.ps1`.
2. Изучить относящиеся к задаче файлы и существующие тесты.
3. Перед критической операцией проверить область действия через `security-guard.ps1`.
4. Выполнить изменения в пределах workspace.
5. Сократить чрезмерно длинный вывод через `tool-output-compress.ps1`.
6. Запустить `post-execution-lint.ps1` для изменённых файлов.
7. Запустить релевантные тесты.
8. Проверить итоговый diff и состояние Git.
9. Сохранить краткую запись о результате и важных ограничениях в `.agent-logs`, если каталог используется проектом.

## Ограничения

- Не удалять файлы, каталоги или историю Git без явного запроса и отдельной проверки безопасности.
- Не писать за пределами `C:\develop\super_nikel` без явного разрешения.
- Не считать отсутствие локального lint-инструмента успешной полной проверкой: это нужно указать в результате.
- Не передавать пользователю необработанный огромный вывод команд, если его можно сжать.
- Не пропускать проверку изменённого кода без указания причины.
