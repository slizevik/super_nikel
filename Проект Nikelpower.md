# Проект Nikelpower

> Сервис для учёных-материаловедов: поиск знаний в графе исследований через диалог с LLM.

---

## Часть 1. Описание проекта

### 1.1. Что это

**Nikelpower** — сервис для учёных-материаловедов, позволяющий искать информацию в общей базе исследований, докладов, статей и презентаций через диалог с LLM. Учёные могут загружать свои документы, а система извлекает из них знания, строит граф связей и делает их доступными для семантического и структурированного поиска.

### 1.2. Зачем это нужно

Материаловедение — область, где знания распределены по тысячам публикаций, отчётов и презентаций. Исследователю сложно:

- найти все эксперименты по конкретному материалу и процессу;
- сравнить отечественную и зарубежную практику;
- увидеть противоречия между источниками;
- понять, где есть пробелы в данных.

Сервис решает эти задачи за счёт:

- **единой базы документов** с метаданными;
- **графа знаний**, отражающего связи «материал → процесс → оборудование → результат»;
- **диалогового интерфейса**, который сам подбирает релевантные источники и формирует ответ со ссылками на оригиналы.

### 1.3. Пользовательские сценарии

1. **Загрузка документа.** Учёный загружает PDF, выбирает категорию, система обрабатывает документ и добавляет его в базу. Прогресс виден пошагово.
2. **Поиск через чат.** Учёный задаёт вопрос на естественном языке (например, «железо сплав»), система ищет по графу и векторному индексу, возвращает список документов с summary, авторами, датами и ссылками на скачивание.
3. **Фильтрация.** Пользователь ограничивает поиск по типу процесса, материалу, географии, году.
4. **Работа с историей.** Чаты сохраняются, можно возвращаться к предыдущим обсуждениям.
5. **Визуализация связей.** Отображаются цепочки «материал → процесс → оборудование → результат», связанные эксперты и лаборатории.

### 1.4. Ключевые принципы

- **Данные только реальные.** LLM не выдумывает документы — все метаданные и ссылки подставляет backend из БД.
- **Граф — не самоцель.** Граф нужен там, где он реально помогает: фильтры, цепочки, пробелы. Простой семантический поиск — через векторный индекс.
- **Строгая онтология.** Извлекаются только сущности из закрытого списка, в ограниченном количестве. Никакого «мусора в графе».
- **Разделение слоёв.** Хранение файлов, метаданных, графа и векторов — независимые сервисы с чёткими контрактами.
- **Переносимость LLM.** Бизнес-логика не знает, откуда модель: внешний API для прототипа, локальный inference в институте.

## Часть 2. Стек технологий

| Слой | Технология | Назначение |
|:---|:---|:---|
| **Язык** | Python | Backend, ML-пайплайны |
| **Frontend** | React 18 + TypeScript | Интерфейс пользователя |
| **Визуализация графа** | react-cytoscapejs | Интерактивные графы, подсветка противоречий |
| **Backend** | FastAPI | REST API, оркестрация |
| **Фоновые задачи** | Celery + Redis | Асинхронная обработка документов |
| **Парсер PDF** | **Docling (IBM)** | PDF → Markdown + картинки с метаданными |
| **Конвертация** | LibreOffice headless | Fallback для DOCX/PPTX → PDF |
| **Граф знаний** | Neo4j + Graphiti Zep | Хранение сущностей, связей, эпизодическая память |
| **Метаданные и чаты** | PostgreSQL 15 + pgvector | История чатов, метаданные документов, векторный поиск |
| **Хранилище файлов** | PostgreSQL `bytea` (MVP) → MinIO | Исходные PDF/DOCX/PPTX |
| **LLM (текст)** | **Yandex GPT 5** | Анализ текста, извлечение сущностей, генерация ответов |
| **LLM (vision)** | **Yandex GPT 5 Vision** | Анализ графиков, таблиц, схем |
| **Embedding** | multilingual-e5-large | Векторное представление чанков |
| **Оркестрация** | docker-compose | Локальная разработка и деплой |

> Версии библиотек не фиксируются в документе — определяются на этапе сборки, чтобы не блокировать обновления безопасности.

## Часть 3. Онтология

### 3.1. Сущности (узлы графа)

| Сущность | Описание | Примеры |
|:---|:---|:---|
| `Material` | материал | никель, сульфат никеля, гарниерит, сплав Fe-Ni |
| `Process` | процесс | кучное выщелачивание, биоокисление, автоклавная плавка |
| `Equipment` | оборудование | реактор, колонна, автоклав, флотационная машина |
| `Property` | свойство | концентрация, pH, температура, прочность на разрыв |
| `Experiment` | эксперимент | серия опытов, описанная в статье |
| `Publication` | публикация | статья, доклад, отчёт |
| `Document` | загруженный документ | PDF/DOCX/PPTX с метаданными |
| `Expert` | эксперт | автор, исследователь |
| `Facility` | лаборатория или институт | ИМет УрО РАН, ЦНИИчермет |
| `Condition` | условие | холодный климат, кислая среда, режим 80°C |
| `Country` | страна | Россия, Китай, Австралия (для фильтра «своё/зарубежное») |
| `Claim` | утверждение | *(этап 2, для реификации противоречий)* |

### 3.2. Связи (рёбра графа)

| Связь | Семантика |
|:---|:---|
| `uses_material` | процесс или эксперимент использует материал |
| `operates_at_condition` | процесс или оборудование работает при условии |
| `produces_output` | процесс или эксперимент производит результат |
| `described_in` | сущность описана в документе |
| `validated_by` | результат подтверждён экспертом или публикацией |
| `contradicts` | противоречие *(этап 2, через Claim)* |

### 3.3. Правила извлечения

- **Тип сущности** — только из закрытого списка.
- **Ограничение объёма** — не более 5 сущностей каждого типа и 10 связей на документ.
- **Дедупликация** — через `canonical_label` + `aliases` (Fe / Iron / Железо → `Fe`).
- **Формат ответа LLM** — валидный JSON, валидация через Pydantic.
- **Отсечка шума** — общие понятия («исследование», «результат», «метод») не извлекаются.
- **Порог значимости** — сущность попадает в граф, если встречается ≥ N раз, или связана обязательной связью, или упомянута в заголовке/аннотации/выводах.

## Часть 4. Целевой Pipeline загрузки документа
1. Пользователь загружает PDF через React-интерфейс
   ↓
2. Backend принимает файл, создаёт job, возвращает job_id
   ↓
3. Docling парсит PDF → document.md + images/ + manifest.json
   (сохранение структуры: заголовки, таблицы, формулы, подписи к картинкам)
   ↓
4. Фильтрация изображений (отсеиваем декоративные)
   ↓
5. Текст + картинки отправляются в Yandex GPT (multimodal-запрос):
   - Модель анализирует текст статьи
   - Для каждой картинки: тип (график/таблица/схема), ключевая информация
   - Результат: enriched_document.md (текст + описания картинок)
   ↓
6. Извлечение сущностей и связей (Extraction-LLM, может быть та же Yandex GPT)
   ↓
7. Канонизация + валидация (Pydantic)
   ↓
8. Запись в БД:
   - Исходный PDF → filestore (Postgres bytea)
   - Метаданные → PostgreSQL
   - Сущности и связи → Neo4j через Graphiti Zep
   - Чанки + embedding → pgvector
   ↓
9. Прогресс через Redis → React опрашивает GET /jobs/{job_id}/status
